## English draft

**Subject:** Request for clarification/permission: independent Android client using NextDNS API, name and optional monetization

Hello NextDNS team,

I am developing an independent Android client that lets users manage their own NextDNS profiles using their own API keys. The app is a native Kotlin/Jetpack Compose client, not an official NextDNS product. It reads settings and DNS logs, supports profile/rule management and opt-in notifications. I intend to distribute it via Google Play after privacy, security and real-device testing.

Could you please clarify the following separately in writing?

1. May an independent third-party Android application access your documented API with each user's own API key, including in a public Google Play release?
2. Are there API rate limits, additional contractual terms, approval procedures or restrictions on commercial/monetized clients?
3. May the app refer to “NextDNS” descriptively in its title or store listing (for example, “an unofficial client for NextDNS”)? What branding and attribution language do you require?
4. Does using NextDNS branding, logo, shield icon, colors or design assets require explicit permission? If permitted, please specify which assets and usage rights.
5. Would advertising inside this third-party client be permissible? Would a one-time digital purchase that permanently removes ads be permissible? The first planned production release will contain no ads or purchases.
6. Is a prominent disclaimer stating that the application is independent and not affiliated with or endorsed by NextDNS sufficient for your preferred presentation?
7. Whom should I contact regarding API/brand policy changes?

I will not claim official affiliation. I will not sell NextDNS accounts/subscriptions, collect users' API keys in my own backend, or represent my app as providing NextDNS service itself.

Thank you for providing the applicable written terms, guidelines or an authorized response.
